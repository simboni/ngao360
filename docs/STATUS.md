### Pilot hardening: security review fixes (this pass)

Every finding of the pilot security review was checked against the code; all 22 were confirmed and fixed with regression tests (commits `fix(auth)`, `fix(privacy)`, `fix(messaging)`, `fix(deploy)`):

- **Sign-in and second factors** (`test/auth-review-fixes.integration.spec.ts`, admin and passkey suites): a one-administrator MFA reset is refused for privileged accounts (any MFA-requiring permission or role) and for targets holding access the actor lacks, so those go through two-person account recovery; the holder always gets an `mfa_reset` security alert. A registered passkey sets `mfaEnabled` and is a second factor for sign-in, TOTP enrolment (MFA session + re-auth) and re-authentication; password-only re-auth is refused for passkey-only accounts, and both re-auth dialogs offer a passkey (AR7). Wrong re-auth passwords count towards the lockout, are audited (`auth.reauth.failed`) and revoke the session at the limit. Second-factor attempts are reserved atomically (`UPDATE … WHERE not locked RETURNING`) before checking, so concurrent guesses cannot exceed `MFA_MAX_FAILURES`. Sign-in answers identically (message and argon2 timing) for unknown, locked and inactive accounts. The password lock no longer applies to a recognised device (an IP with a sign-in in the last 30 days) or to passkey sign-in, and the per-account limiter is keyed by account + client IP, so an outsider cannot lock the real person out; the holder is alerted when a lock engages.
- **Tenancy and privacy** (`rls`, `office-privacy-review`, `field-privacy-review` suites; migration `20261201000000_privacy_review_fixes`): `tenants` has RLS (own tenant inside a tenant transaction, all for a platform tenant, read-only without a context) and column-level UPDATE grants (never id, slug, type, status, demo flag). Case, referral and correspondence edits audit personal free text by field name only (`changedFreeTextFields`). `office.retention` runs for every tenant whatever its status or module state and now also erases ended appointments' requester contacts; appointments and agents have audited erasure endpoints (re-auth; agents also when WITHDRAWN) and erased data cannot be restored (triggers); the new `field.agent_retention` job erases withdrawn agents' ID, phone, M-Pesa and next of kin after `agentSensitiveRetentionMonths` (default 12). Historical-demo organisations serve no public portal or projects and cannot switch them on.
- **Messaging** (`platform-delivery`, `platform-adapters` suites): anonymous portal SMS go only to `CITIZEN_SMS_ALLOWED_PREFIXES` (default `+254`), at most `CITIZEN_MESSAGES_PER_DESTINATION_PER_DAY` per address and `CITIZEN_SMS_DAILY_BUDGET_PER_TENANT` per tenant, and never without a portal captcha while a paid SMS provider is configured (skipped, never failing the submission; fail closed if the counter store is down). The dispatcher renews each row's lease just before sending and skips rows another worker took over. Africa's Talking: an ambiguous outcome (timeout or dropped connection after the request was written, unreadable 2xx) is not resent; 401/403 are not retried and are logged as configuration faults. A tenant's disabled e-mail / SMS / push integration skips its messages on that channel, except account-security messages (invitation, recovery link, security alert, contact verification), which always use the deployment channel.
- **Production stack** (`test/deploy-config.spec.ts`, hadolint, compose schema check): the API and worker hold only the `ngao_app` URL; a new non-superuser schema owner `ngao_owner` (created by `infra/postgres/init-roles.sh`, owns the database; migrations verified as a non-superuser owner on PostgreSQL 16) runs `migrate` and `backup`; the backup image is built (`deploy/backup/Dockerfile`) instead of installing packages on a network with no route out, and writes outside the checkout; Caddy redacts the SMS callback token from access logs and can allow-list the vendor's addresses (`AT_WEBHOOK_ALLOWED_IPS`); `.env.prod` (any non-example env file), `backups/`, `.load/` and dumps are git- and docker-ignored; clamd runs with an explicit read-only `deploy/clamav/clamd.conf` (`AlertExceedsMax`, `AlertEncrypted`, `AlertBrokenExecutables`, limits above the 25 MiB upload maximum) and a limits-exceeded reply is INFECTED, never CLEAN.

Caveats: audit rows written before this pass keep the free text they recorded (the log is append-only by design); the Caddyfile was not loaded by a Caddy binary here (no Docker, no binary).

### Demo review findings

All 8 reviewer findings were checked against the code and confirmed; each is fixed with a regression test (`apps/api/test/demo-2022.e2e.spec.ts` "review fixes", `apps/api/test/demo-34a-import.integration.spec.ts`, `packages/shared/src/demo-2022/demo-2022.test.ts` "review fixes", `packages/shared/src/admin/admin.test.ts`):

1. **Tenant takeover via `--tenant` (high):** the builder looks the slug up first and refuses an existing organisation that is not a historical demo; it never relabels, renames or adds synthetic users to it.
2. **`--redacted` skipped the hold:** every imported scan is now held; `--redacted` writes a `file.display_hold.redaction_declared` audit event naming the declarer, and only a different person with `tally.approve` releases the hold.
3. **Importer and redact CLI on any tenant, MFA treated as passed for anyone:** both require a historical demo organisation (and the importer a `HISTORICAL_DEMO` cycle); `authFor` acts only as the synthetic `…@<slug>.example.org` users of a demo organisation, so no real account is impersonated past the MFA check.
4. **Audit-log CSV had the label only:** it now carries the banner, the unofficial disclaimer, the label and the notice (deployment roster and campaign exports aligned the same way).
5. **Re-run after a config change kept old figures:** the builder refuses when the cycle already has a simulated registry from a different layer; source and note edits no longer change the fingerprint.
6. **Docs claimed real 34A codes would map onto the generated registry:** corrected (only county, constituency and ward segments can match; real stations still go through the draft registry).
7. **Foreign-county codes filed under Bungoma units:** codes whose county is not in the demo registry are reported and skipped, and draft lookups are keyed by county + code.
8. **Duplicated `constituencyTotals` code crashed the generator:** the loader reports duplicates and missing or unknown codes as a `DemoConfigError`.

### What is real and what is simulated

- Real (public, historical reference): the county name and number, the 9 constituency names; the 45 ward names are used but still marked unverified.
- Simulated: polling centres and stations, their codes beyond the inferred pattern, registered voters per station, every 37A/37B/37C figure, the form images (SIMULATED watermark), the users, reviewers and timing. County totals are UNVERIFIED placeholders and candidates are "Candidate A (simulated)" etc. until verified gazetted totals and names are supplied.
